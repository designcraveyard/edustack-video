# Character description block

The character description block is the **text contract** that locks character identity across the whole pipeline. Every storyboard and clip prompt pastes it IDENTICALLY into a `CHARACTERS:` section — the model sees the same paragraph every call, so identity doesn't drift between beats.

Phase 3a produces this block in two shapes, depending on `character_mode`:

| `character_mode` | Source file | How it's generated |
|---|---|---|
| `human` | `characters/descriptions.json` | Drawn from the script's `## Cast` block; written as part of the rich sheet generation. Same paragraph appears on the sheet PNG and in the JSON. |
| `abstract` | `characters/descriptions.json` | Same as `human`, but the cast's `looks` field describes stylised non-human concepts (e.g. "abstract watercolour herbivore mascot blending deer-like ears and rabbit softness"). |
| `none` | `characters/description_block.md` | Generated by Gemini 2.5 Pro from the script's topic and notes when there's no `## Cast` block to pull from. No sheet PNG. |

Downstream consumers — `phase_storyboard.py` and `phase_clips.py` — read in this precedence:

1. `descriptions.json` → join each character's `verbatim_description` into a CHARACTERS block.
2. `description_block.md` → use verbatim (already structured markdown).
3. Legacy `analysis.json.checks.characters_present` → thin label fallback only.

## descriptions.json shape (human / abstract)

```json
{
  "style": "Pixar",
  "style_descriptor": "Pixar 3D animated film aesthetic, soft directional lighting, smooth subsurface materials, expressive characters, shallow depth of field.",
  "characters": [
    {
      "name": "Jay",
      "slug": "jay",
      "role": "Class-7 hockey player who keeps cutting across the road",
      "personality": "Determined, easily distracted by his hockey daydreams, warm and well-meaning. Strong inner monologue, mild stubborn streak.",
      "voice_tone": "Casual Hinglish, energetic, mid-paced. Rises when he gets excited about a goal he's imagining.",
      "looks": "A slightly taller child silhouette with determined eyebrows, warm brown skin, dark hair, and a clear hockey-stick pose that reads instantly.",
      "verbatim_description": "A slightly taller child silhouette with determined eyebrows, warm brown skin, dark hair, and a clear hockey-stick pose that reads instantly. Role: Class-7 hockey player who keeps cutting across the road Personality: Determined, easily distracted by his hockey daydreams, warm and well-meaning. Strong inner monologue, mild stubborn streak. Voice & tone: Casual Hinglish, energetic, mid-paced. Rises when he gets excited about a goal he's imagining."
    }
  ],
  "off_sheet_extras_count": 0
}
```

The `verbatim_description` field is what storyboard + clip prompts paste in. It's the same paragraph that appears on the sheet PNG under the character's name.

## description_block.md template (none mode)

When `character_mode: none`, we skip the sheet but still produce a structured continuity block. Gemini 2.5 Pro generates it from the script's topic + notes; the template it emits looks like this:

```
## Characters

- **<name or role>** (recurring): <species/age> · <build/height> · <hair: color, style, length> · <eyes: shape, color> · <skin/coat: tone, texture> · <signature outfit: top, bottom, accessory> · <key prop or expression>.
- **<name or role>**: <same fields>.
- ...

## Crowd / extras

- <describe the crowd's collective character: e.g., "village children, mixed skin tones, simple cotton clothes, ages 6–10">.

## Consistency notes

- All character heights are consistent across shots: <character X> is taller than <character Y> by ~1 head.
- Lighting on faces is soft, three-quarter front-lit.
- No reflective sunglasses (image models tend to embed weird reflections).
```

## Rules (apply to both shapes)

1. **Concrete, visual nouns only.** "Confident" is not visual. "Hands on hips, chin up" is. "Warm brown skin, dark hair, determined eyebrows" is.
2. **Locked palette.** Once a colour is named for hair/outfit/coat, never restate it differently elsewhere. The palette is set on the sheet (BOTTOM CENTER region) and reused identically downstream.
3. **Limit to ~6 named features per character.** More invites drift. The Cast block's `looks` field naturally caps around 1–2 sentences for this reason.
4. **Tag-friendly tail.** End each `looks` line with a comma-separated tag list so the generator can fall back on tags if it misreads prose.
5. **One source of truth.** When a character's description changes, edit the script's Cast block. `phase_characters.py` re-derives `descriptions.json` and the sheet on the next run; you never edit `descriptions.json` directly.

## Why this matters

Without a description block, every storyboard prompt asks the model "draw two characters consistent with the sheet image you already have"
— and that works for the panel layout but **fails for Seedance i2v** (which sees the keyframe image but doesn't read the storyboard prompt's character intent). Phase 4 clips drift hard without the verbatim text. The description block is what keeps Jay's eyebrows determined and his jersey blue across all 12 clips.
